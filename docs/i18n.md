# Shared interface languages

`@remote-codex/thread-ui/i18n` owns the `en` / `zh-CN` resources, locale store,
React context, language selector, and Intl helpers. The root package re-exports the
public helpers. Host applications mount `I18nProvider` once; shared panels and host
components consume `useI18n()`. Standalone shared components also subscribe to the
same store. A `Symbol.for('remote-codex.i18n')` store keeps separately bundled/lazy
entry points synchronized without remounting components or resetting drafts.

The saved `remote-codex.locale` browser preference wins over navigator languages.
Common `en-*`, `en_*`, `zh-*`, `zh_*`, English/Chinese and Chinese-name aliases
normalize to the two supported locales. Unsupported saved preferences and unsupported
browser languages fall back to English. All Chinese variants use simplified Chinese.
Switching updates `html.lang` / `dir`, saves the canonical preference, and notifies
subscribers; other tabs follow storage events. If browser storage is denied, switching
still works for the current page.

## Product copy

Resources are paired `<namespace>.en.ts` / `<namespace>.zh-CN.ts` modules, assembled
by `en.ts` / `zh-CN.ts`. The namespaces are `common`, `workbench`, `chat`, `files`,
`settings`, `devices`, `auth`, and `sharing`. Global search adds its own `search`
namespace during integration. Existing conversation search lives in `chat`.

```tsx
const { t, locale } = useI18n();
return <button aria-label={t('files.saveFile')}>{t('files.saveFile')}</button>;
```

Non-React formatting helpers use `translate(key, values)` (also exported as `t`).
`TranslationKey` derives from the English catalog, and the Chinese aggregate uses
`satisfies Record<keyof typeof en, ...>`. Keys are named after product concepts; a
few migrated duplicate phrases have stable suffixes to keep meanings separate.

Add a phrase to both namespace files, then use its key at the display boundary.
Interpolation uses `{{name}}` and a values object; missing interpolation values and
unknown runtime keys throw. Inserted values are literal text, never reinterpreted
as placeholders or HTML. Plurals use `{ one, other }` plus `count` and
`Intl.PluralRules`; `formatDate` / `formatNumber` and the shared display formatters
use the selected locale. Missing locale entries resolve through the English catalog.
`src/i18n/i18n.test.tsx` checks key/placeholder parity, nonempty values, alias/fallback,
storage recovery, cross-tab switching, shared subscriptions, Intl formatting, and
harness-facing attachment-token invariance.

For another language, update `locales.ts`, add matching namespace modules, register
its aggregate in `resources`, extend the selector, and extend the parity tests.

Use subscriptions only in components or custom hooks; lazy import factories must
remain ordinary functions. Locale-dependent `useMemo` values need the locale in
their dependency array. The returned `t` function has stable identity and reads the
current store at call time; use `[locale, ...inputs]` for cached display labels, not
`[t]`. Translate new operation notices when the operation finishes rather than at
module import. Notices already stored in state retain their occurrence language.
Module-level product-label tables use getters so language
changes do not capture the initial locale. Keep protocol/state values separate from
localized labels.

User/model messages, file contents and names, commands/paths, model IDs, API fields,
native Hook defaults, and attachment prompt markers must remain unchanged. Third
party/capability labels and raw service errors retain their original text.
